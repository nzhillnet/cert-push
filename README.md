# cert-push

acme.sh-based Let's Encrypt certificate issuance, for a home lab with more than one host.
One command issues or renews a cert via Cloudflare DNS-01 and pushes it to the right host
over SSH, running whatever reload command that service needs — instead of hand-running
`certbot`/`acme.sh` and scp-ing certs around every time something's about to expire.

Full write-up, with the reasoning behind the design: **https://hillnet.co.nz** (search the
site for "certificate" / "acme.sh" — there isn't a single dedicated post for this one yet).

This is **not a drop-in product**. It's wired to my own fleet of hosts and my own Cloudflare
zone. What's genuinely reusable is the pattern: one YAML file describing every host and how
to reload it, one script that issues, deploys, and registers the deploy hook with acme.sh
so future renewals deploy themselves automatically. If you're managing certs across your
own home lab, this is meant to be read and adapted, not deployed as-is.

## How it works

```
manage-certs.sh --host app1
  │
  ├─ acme.sh --issue --dns dns_cf  (Cloudflare DNS-01, no port 80/443 needed anywhere)
  ├─ writes a small deploy.sh for that host (scp-over-ssh the three PEM files, run reload_cmd)
  └─ acme.sh --install-cert --reloadcmd "bash deploy.sh"
       → every future renewal (acme.sh's own cron, ~60 days) re-runs that deploy automatically
```

Nothing public needs to listen on 80/443 for issuance — DNS-01 means a host can sit on a
fully internal network and still get a real Let's Encrypt certificate.

## Setup

1. `bin/install-acme.sh` — installs acme.sh, points it at Let's Encrypt, installs acme.sh's
   own renewal cron job. One-time, on whichever host will run `manage-certs.sh`.
2. Create `~/.secrets/cloudflare.env` (chmod 600):
   ```
   CF_Token="<a Cloudflare API token scoped to DNS edit on your zone only>"
   CF_Account_ID="<your account ID>"
   ```
3. Copy `hosts.conf.yaml.example` to `hosts.conf.yaml` and add your own hosts — see the
   patterns in the example file (standard nginx reload, PKCS12 bundle build, non-root
   ownership fix, sudo-only write access, localhost/the workstation itself).
4. Deploy the SSH key this tool will use to reach each target host:
   ```
   ssh-copy-id -i ~/.ssh/cert-deploy root@<host>
   ```
5. Issue and deploy:
   ```
   bin/manage-certs.sh --host app1 --dry-run   # see what it would do first
   bin/manage-certs.sh --host app1
   ```
   A `SUCCESS` line means the cert is issued and live on the host. Re-run the same command
   whenever you change that host's `reload_cmd` or paths in `hosts.conf.yaml` — the deploy
   hook registered with acme.sh is only regenerated by this command, not by a plain renewal.

## What's included

| File | What it does |
|---|---|
| `bin/manage-certs.sh` | The core: issue/renew via acme.sh + Cloudflare DNS-01, build and run a per-host deploy script over SSH, register it as the acme.sh reload hook so future renewals self-deploy. `--host <name>` to process one host, `--dry-run` to preview. |
| `bin/install-acme.sh` | One-time acme.sh install + Let's Encrypt default CA + renewal cron. |
| `bin/cert-expiry-report` | Daily check: reads the certificate actually **deployed** on each host (not just acme.sh's own renewal log — catches a renewal that issued fine but never reached the host), plus any `EXTRA` endpoints you list that aren't managed by this tool at all. E-mails a summary when something's close to expiry or a check fails. |
| `bin/unifi-ssl-import.sh` | Worked example of a `reload_cmd` for a trickier target: a UniFi OS Server host, where the Let's Encrypt cert has to go on an nginx TLS front rather than into UniFi's own internal certificate store. |
| `hosts.conf.yaml.example` | The host list schema, with one example per deploy pattern. Copy to `hosts.conf.yaml` and fill in your own. |

## `hosts.conf.yaml` schema

```yaml
domain: internal.example.com      # each host's cert is issued for <name>.<domain>
cloudflare_zone: example.com      # the CF zone your API token is scoped to

hosts:
  - name: app1                    # becomes app1.internal.example.com
    deploy_target: 192.0.2.11     # or "localhost" for the workstation itself
    deploy_user: root
    remote_cert_path: /etc/ssl/app1/
    remote_key_path: /etc/ssl/app1/
    reload_cmd: "systemctl reload nginx"
    transfer_sudo: false          # true = write via "sudo tee" instead of "cat >"
    keylength: ""                 # e.g. "2048" to force RSA instead of acme.sh's default ECC
```

## Requirements

- [acme.sh](https://github.com/acmesh-official/acme.sh)
- A Cloudflare-managed DNS zone and an API token scoped to DNS edit on it
- SSH key access (`~/.ssh/cert-deploy`) to every target host
- Python 3 with `pyyaml` (used to parse `hosts.conf.yaml`)
